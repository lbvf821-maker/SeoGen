# Анализ и исправление промпта для OpenAI Assistant

## 🔴 Критические проблемы в исходном промпте

### 1. СТРУКТУРА JSON НЕВАЛИДНА
**Проблема:**
```json
{
  "assistant_profile": {
    "core_rules": [...]
  },
  "additionalInfo": {...},

  {  // ← ЭТО ОШИБКА! Второй блок внутри первого
    "assistant_profile": {
      "core_rules": [...]
    },
    "additionalInfo": {...}
  }
}
```

**Следствие:** OpenAI API не может распарсить промпт, часть инструкций игнорируется.

**Исправление:** Объединил блоки в единую валидную структуру.

---

### 2. ПРОТИВОРЕЧИЕ В ПРАВИЛАХ ПРО АДРЕС

**Проблема:**
- В `core_rules`: "Не обещай наличие/сроки/цену без уточнения"
- Во втором блоке: "Адрес склада — отвечать сразу, если есть в базе"
- Клиент спрашивает адрес → модель не знает, какое правило применить

**Следствие:** Модель не выдает адрес, хотя он есть в базе знаний.

**Исправление:**
```json
"ТОЧНЫЕ ФАКТЫ: Если вопрос требует точного факта (адрес склада, город,
реквизиты, контакты) - отвечай ТОЛЬКО по базе знаний. Адрес склада:
Нижний Новгород, Ореховская, 1."

"ОПЕРАТИВНЫЕ ДАННЫЕ: Если вопрос требует оперативных данных (наличие
конкретной позиции, точная цена, точные сроки) - говори 'уточним в КП'."
```

Теперь четко разделены:
- **Факты** (адрес, контакты) → отвечать сразу
- **Оперативные данные** (наличие, цена) → уточним в КП

---

### 3. ЛОГИКА ИМЯ/ТЕЛЕФОН НЕ РАБОТАЕТ

**Проблема:**
```json
"phase6A": {
  "result": {
    "option7": "Клиент предоставил имя и номер телефона",
    "option6A": "Клиент предоставил только имя или только телефон"
  }
}
```

Но phase6B и phase6C существуют, но на них нет явных переходов из phase6A!

**Следствие:** Модель не знает, когда переходить к phase6B/phase6C, поэтому не запрашивает недостающий контакт.

**Исправление:**
```json
"phase_5_contacts": {
  "branches": {
    "only_phone": {
      "condition": "{phone} заполнен, {name} пустое.",
      "task": "Поблагодари. Уточни имя.",
      "next": ["phase_6_confirmation"]
    },
    "only_name": {
      "condition": "{name} заполнено, {phone} пустое.",
      "task": "Поблагодари. Попроси телефон.",
      "next": ["phase_6_confirmation"]
    },
    "both_provided": {
      "next": ["phase_6_confirmation"]
    }
  }
}
```

Теперь явно прописаны ветвления для каждого случая.

---

### 4. ФОРМАТ ДЛЯ ALBATO ЛОМАЕТ JSON

**Проблема:**
```json
"task": "...\n[systemTextByAi: {\"trigger\":\"NEWLEAD\",\"name\":%%\"{name}\"%%,...}]"
```

Символы `%%` не являются валидным JSON-экранированием. OpenAI может не распознать это как корректный формат.

**Следствие:** `[systemTextByAi: {...}]` может не выводиться или выводиться некорректно.

**Исправление:**
```json
"system_output": "[systemTextByAi: {\"trigger\":\"NEWLEAD\",\"name\":\"{name}\",\"phone\":\"{phone}\",...}]"
```

- Убрал `%%` из JSON-промпта
- Оставил обычные экранированные кавычки `\"`
- Если Albato требует `%%`, настройте это на стороне Albato (препроцессинг), а не в JSON

---

### 5. ИЗБЫТОЧНАЯ ДЛИНА И СЛОЖНОСТЬ

**Проблема:**
- 8 фаз с вложенными опциями
- Множество повторений одних и тех же правил
- Длина промпта ~6000 токенов

**Следствие:**
- Модель "теряется" в фазах
- Высокая стоимость каждого запроса
- Снижение качества следования инструкциям

**Исправление:**
- Сократил до 7 ключевых фаз
- Убрал дублирование правил
- Объединил связанные задачи (сбор ТЗ в одну фазу)
- Итоговая длина ~3500 токенов (-40%)

## ✅ Что исправлено в новой версии

### 1. Валидная структура JSON
- Единая иерархия без дублирования
- Все блоки корректно закрыты
- Проверено валидатором JSON

### 2. Четкие правила для фактов vs оперативных данных
```
ФАКТЫ (адрес, контакты) → отвечать сразу по базе знаний
ОПЕРАТИВНЫЕ ДАННЫЕ (наличие, цена) → "уточним в КП"
```

### 3. Явная логика контактов
```
Дан только телефон → спроси имя
Дано только имя → спроси телефон
Даны оба → переход к подтверждению
```

### 4. Корректный формат вывода для Albato
```
[systemTextByAi: {"trigger":"NEWLEAD","name":"{name}","phone":"{phone}",...}]
```

### 5. Упрощенная структура фаз
```
1. Greeting → 2. Qualification (ГОСТ/Импорт/Нет марки) →
3. Requirements (ТЗ) → 4. Delivery & Docs →
5. Contacts (имя+телефон) → 6. Confirmation → 7. Support
```

### 6. Приоритет правил в начале
Самые важные правила вынесены в топ `core_rules`:
1. Сначала ответь на вопрос
2. Точные факты = по базе
3. Оперативные данные = "уточним в КП"
4. ГОСТ → предложить импорт
5. Контакты = имя + телефон

## 🎯 Рекомендации по настройке в OpenAI Assistants

### 1. Загрузка промпта
- Используйте файл `openai_assistant_prompt_fixed.json`
- Скопируйте содержимое в поле "Instructions"
- ИЛИ загрузите как файл и используйте в Assistant

### 2. Настройка File Search
- Загрузите базу знаний как отдельный текстовый файл (не JSON)
- Формат:
```
Вопрос: Где находится склад ООО «ВЭМ»?
Ответ: Склад находится в Нижнем Новгороде, Ореховская, 1.

Вопрос: Чем занимается ООО «ВЭМ»?
Ответ: ООО «ВЭМ» поставляет высококачественные импортные...
```

### 3. Настройка модели
- Рекомендуется: `gpt-4-turbo` или `gpt-4o` для сложной логики
- Температура: `0.3-0.5` (баланс точности и естественности)
- Max tokens: `800` (ограничение на длину ответа ~400 символов)

### 4. Настройка Albato
**ВАЖНО:** Формат `%%"{name}"%%` нужно настроить на стороне Albato:

1. В Albato создайте правило парсинга:
   - Входящий текст: `[systemTextByAi: {...}]`
   - Извлечь JSON между `: ` и `]`
   - Распарсить JSON и извлечь поля

2. Или настройте препроцессор в Wazzup24:
   - Перед отправкой в Albato заменить `"{name}"` на `%%"{name}"%%`

### 5. Тестирование
Проверьте эти сценарии:

**Сценарий 1: Вопрос про адрес**
```
Клиент: Где находится ваш склад?
Ожидаемый ответ: Наш склад находится в Нижнем Новгороде,
Ореховская, 1. Организуем доставку или самовывоз. Что Вас интересует?
```

**Сценарий 2: Только телефон**
```
Клиент: Вот мой номер: 89067778899
Ожидаемый ответ: Спасибо! Сохранила номер +79067778899.
Подскажите, пожалуйста, как к Вам обращаться?
```

**Сценарий 3: Только имя**
```
Клиент: Меня зовут Иван
Ожидаемый ответ: Иван, отлично! Оставьте, пожалуйста,
номер телефона для отправки КП.
```

**Сценарий 4: Имя + телефон**
```
Клиент: Иван, 89067778899
Ожидаемый ответ: Иван, спасибо! Ваша заявка принята.
Подготовлю коммерческое предложение и свяжемся с Вами в ближайшее время.
[systemTextByAi: {"trigger":"NEWLEAD","name":"Иван","phone":"+79067778899",...}]
```

## 🔧 Дополнительные улучшения

### 1. Добавлено в исправленный промпт
- Явное указание "женский голос" в tone
- Приоритет правил в порядке важности
- Четкое разделение `task_internal` и `task_client` в фазе подтверждения
- Список всех переменных в одном месте

### 2. Если проблемы остаются

**Модель не видит адрес из File Search:**
- Убедитесь, что база знаний загружена как файл в Assistant
- Включите "File Search" в разделе Tools
- Добавьте дублирующую информацию прямо в промпт (как я сделал):
```json
"priority_facts": [
  "Адрес склада: Нижний Новгород, Ореховская, 1"
]
```

**Модель все еще не запрашивает имя после телефона:**
- Проверьте, что модель `gpt-4` (не `gpt-3.5-turbo`)
- Снизьте температуру до 0.3
- Добавьте в Instructions в самом начале:
```
ТЫ ОБЯЗАНА ЗАПРОСИТЬ ИМЯ, ЕСЛИ ПОЛУЧЕН ТОЛЬКО ТЕЛЕФОН.
ТЫ ОБЯЗАНА ЗАПРОСИТЬ ТЕЛЕФОН, ЕСЛИ ПОЛУЧЕНО ТОЛЬКО ИМЯ.
```

**Albato не получает данные:**
- Проверьте логи Wazzup24: доходит ли текст с `[systemTextByAi: {...}]`?
- Настройте webhook в Albato на извлечение JSON из текста сообщения
- Используйте регулярное выражение: `\[systemTextByAi: (.+?)\]`
