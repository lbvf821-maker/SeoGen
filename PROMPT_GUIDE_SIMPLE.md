## 🎯 Три простых правила

### 1. Будьте конкретны

**❌ Плохо:**
```
Сделай телеграм бота для работы с базой данных
```

**✅ Хорошо:**
```
Создай телеграм бота на Python с библиотекой aiogram 3.x, который:
- Подключается к PostgreSQL базе данных
- Имеет команды: /start, /search, /add
- При /search спрашивает марку металла и показывает результаты из БД
- Использует inline кнопки для навигации
```

### 2. Давайте примеры

Всегда показывайте, как должно работать:

```
Пример работы:
Пользователь: /search
Бот: Введите марку металла
Пользователь: Ст3
Бот: Найдено 3 позиции:
     1. Ст3 - 10мм - 50кг
     2. Ст3 - 12мм - 75кг
     [кнопки: Подробнее | Заказать]
```

### 3. Исправляйте точечно

**❌ Не просите:**
```
Перепиши весь файл, исправь ошибку в строке 45
```

**✅ Просите:**
```
Файл: bot.py
Строка 45: ошибка "list index out of range"

Исправь ТОЛЬКО эту строку и окружающий код (±5 строк).
Покажи только исправленный участок.
```

## 🚨 Как избежать повторяющихся ошибок

### Проблема: Claude делает одну и ту же ошибку снова и снова

**Решение:** Создайте файл `RULES.md` в проекте

```markdown
# ПРАВИЛА ДЛЯ CLAUDE

## ❌ НИКОГДА НЕ ДЕЛАЙ:

1. [Ошибка которая повторяется]
   Причина: [почему это плохо]
   Правильно: [как нужно делать]

2. [Другая частая ошибка]
   Причина: [почему это плохо]
   Правильно: [как нужно делать]

## ✅ ВСЕГДА ДЕЛАЙ:

1. [Правило 1]
2. [Правило 2]
3. [Правило 3]
```

**Пример для ваших проектов:**

```markdown
# ПРАВИЛА ДЛЯ CLAUDE

## ❌ НИКОГДА НЕ ДЕЛАЙ:

1. НЕ используй print() в боте - используй logging
   Причина: print не пишет в лог файл
   Правильно: logger.info("сообщение")

2. НЕ оставляй токены и ключи в коде
   Причина: небезопасно
   Правильно: всё в .env файле

3. НЕ делай except Exception без логирования
   Причина: не видно где упал код
   Правильно:
   ```python
   except Exception as e:
       logger.error(f"Ошибка: {e}")
       raise
   ```

4. НЕ забывай await перед асинхронными функциями
   Причина: функция не выполнится
   Правильно: result = await async_function()

5. В HTML формах ВСЕГДА проверяй name у полей ввода
   Причина: без name данные не отправляются на backend
   Правильно: <input type="text" name="username">

## ✅ ВСЕГДА ДЕЛАЙ:

1. Добавляй type hints:
   def function(text: str, count: int) -> list:

2. Обрабатывай ошибки БД:
   try:
       db.execute(query)
   except DatabaseError as e:
       logger.error(f"DB error: {e}")

3. В телеграм ботах отвечай пользователю при ошибке:
   await message.answer("Произошла ошибка, попробуйте позже")

4. Проверяй данные перед записью в БД:
   if not username or len(username) < 3:
       raise ValueError("Неверное имя")

5. В HTML добавляй проверки перед отправкой формы:
   <form onsubmit="return validateForm()">
```

### Как использовать RULES.md

При каждом новом промпте добавляйте в начало:

```
ВАЖНО: Следуй правилам из файла RULES.md

[Ваш основной промпт]
```

## 📦 Готовые промпты для ваших задач

### 1. Телеграм бот для работы с БД

```
КОНТЕКСТ:
Проект: Бот для фильтрации металла
Тип: Телеграм бот с базой данных
База данных: PostgreSQL
AI API: ChatGPT API (для обработки запросов на естественном языке)

ЗАДАЧА:
Создать телеграм бота для поиска металла в базе данных

ТРЕБОВАНИЯ:

Функционал:
1. Команда /start - приветствие и список команд
2. Команда /search - поиск металла по марке, толщине, весу
3. Команда /add - добавить позицию (только для админа)
4. Кнопка "AI поиск" - пользователь пишет текстом что нужно, ChatGPT превращает в запрос к БД
5. Показывать результаты с inline кнопками: [Подробнее] [Заказать]

Технологии:
- Python 3.10+
- aiogram 3.x
- SQLAlchemy
- PostgreSQL
- OpenAI API (ChatGPT)
- Docker
- python-dotenv

Структура БД:
Таблица metals:
- id (int)
- grade (марка металла, str)
- thickness (толщина, float)
- weight (вес, float)
- location (место хранения, str)
- quantity (количество, int)

ПРИМЕРЫ РАБОТЫ:

Пример 1 - обычный поиск:
Пользователь: /search
Бот: Выберите параметр поиска: [Марка] [Толщина] [Вес]
Пользователь: жмет [Марка]
Бот: Введите марку металла
Пользователь: Ст3
Бот:
  Найдено 3 позиции:

  1️⃣ Марка: Ст3, Толщина: 10мм, Вес: 50кг
     Место: Склад А, ряд 5
     [Подробнее] [Заказать]

  2️⃣ Марка: Ст3, Толщина: 12мм, Вес: 75кг
     Место: Склад Б, ряд 2
     [Подробнее] [Заказать]

Пример 2 - AI поиск:
Пользователь: жмет кнопку [AI Поиск]
Бот: Опишите что вам нужно обычным языком
Пользователь: Мне нужен лист стали толщиной около сантиметра
Бот: 🤖 Понял, ищу сталь толщиной 8-12мм...
     [показывает результаты как в примере 1]

Пример 3 - ошибка:
Пользователь: Ст999
Бот: ❌ Ничего не найдено. Попробуйте:
     • Проверить марку металла
     • Использовать AI поиск
     [AI Поиск] [Показать все марки]

ВАЖНЫЕ ПРАВИЛА:

1. Все настройки в .env:
   - BOT_TOKEN=ваш_токен
   - DATABASE_URL=postgresql://...
   - OPENAI_API_KEY=ваш_ключ
   - ADMIN_IDS=123456,789012

2. Логирование всех действий:
   logger.info(f"User {user_id} search for {query}")
   logger.error(f"DB error: {e}")

3. Обработка ВСЕХ ошибок:
   - Нет подключения к БД → "Сервис временно недоступен"
   - Ошибка ChatGPT API → "AI поиск временно не работает, используйте обычный"
   - Неверный формат ввода → "Введите корректное значение"

4. При работе с ChatGPT API:
   - Таймаут 30 секунд
   - Если ошибка - предложить обычный поиск
   - Логировать все запросы и ответы

5. База данных:
   - Использовать connection pool
   - Закрывать соединения после запроса
   - Обрабатывать IntegrityError при добавлении дубликатов

ЧТО НУЖНО В ОТВЕТЕ:

1. Файлы:
   - bot.py (основной код бота)
   - database.py (работа с БД)
   - config.py (настройки из .env)
   - ai_helper.py (работа с ChatGPT API)
   - requirements.txt
   - Dockerfile
   - .env.example
   - README.md (как запустить)

2. Каждый файл с комментариями к сложным местам

3. SQL скрипт для создания таблицы

4. Инструкция:
   - Как установить зависимости
   - Как настроить .env
   - Как создать БД
   - Как запустить бота
   - Как запустить в Docker

НЕ НУЖНО:
- Длинные объяснения как работает aiogram
- Альтернативные варианты архитектуры
- Юнит-тесты (добавлю сам потом)
```

### 2. Веб-приложение с фронтендом и бэкендом

```
КОНТЕКСТ:
Проект: CRM система
Тип: Веб-приложение (FastAPI backend + HTML/CSS/JS frontend)
База данных: PostgreSQL
AI: Нет

ЗАДАЧА:
Создать простую CRM для управления клиентами

ТРЕБОВАНИЯ:

Функционал:

Backend (FastAPI):
1. GET /clients - список всех клиентов (JSON)
2. POST /clients - добавить клиента
3. PUT /clients/{id} - обновить клиента
4. DELETE /clients/{id} - удалить клиента
5. GET /reminders - напоминания на сегодня
6. POST /reminders - создать напоминание

Frontend (HTML):
1. Страница со списком клиентов (таблица)
2. Форма добавления клиента
3. Кнопки редактирования/удаления
4. Всплывающие напоминания
5. Фильтр по имени/телефону

Технологии:
- Python 3.10+
- FastAPI
- SQLAlchemy
- PostgreSQL
- Jinja2 для шаблонов HTML
- Bootstrap 5 для красивого интерфейса
- Docker

Структура БД:

Таблица clients:
- id (int)
- name (str)
- phone (str)
- email (str)
- address (str)
- notes (text)
- created_at (datetime)

Таблица reminders:
- id (int)
- client_id (int, foreign key)
- reminder_type (str: "звонок" или "визит")
- reminder_date (date)
- reminder_time (time)
- notes (text)
- is_done (bool)

ПРИМЕРЫ РАБОТЫ:

Пример 1 - Добавление клиента:
1. Пользователь открывает http://localhost:8000
2. Видит список клиентов (таблицу)
3. Нажимает кнопку "Добавить клиента"
4. Появляется форма:
   - Имя: [____]
   - Телефон: [____]
   - Email: [____]
   - Адрес: [____]
   - Заметки: [____]
   [Сохранить] [Отмена]
5. Заполняет и нажимает "Сохранить"
6. Клиент добавляется в таблицу БЕЗ перезагрузки страницы (AJAX)

Пример 2 - Напоминание:
1. На главной странице справа блок "Напоминания на сегодня"
2. Показывает:
   📞 14:00 - Позвонить: Иван Петров (тел: +7...)
   🏠 16:30 - Визит: ООО Рога и Копыта (адрес: ул...)
3. Кнопка [Выполнено] рядом с каждым
4. При нажатии - напоминание убирается из списка

Пример 3 - Ошибка:
1. Пользователь не заполнил обязательное поле "Имя"
2. При нажатии "Сохранить":
   - Поле "Имя" подсвечивается красным
   - Под полем текст: "Имя обязательно для заполнения"
   - Форма НЕ закрывается
3. После исправления - сохраняется нормально

ВАЖНЫЕ ПРАВИЛА:

1. Frontend (HTML/JS):
   - ВСЕ формы должны иметь атрибут name у input полей
   - Обязательные поля отмечены * и проверяются ПЕРЕД отправкой
   - После успешного действия - показать уведомление: "Клиент добавлен ✓"
   - Все запросы к API через fetch() или axios
   - Обрабатывать ошибки сети: "Нет связи с сервером"

2. Backend (Python/FastAPI):
   - Все эндпоинты возвращают JSON
   - Обязательная валидация через Pydantic
   - Если ошибка валидации - вернуть 400 с описанием
   - Если нет в БД - вернуть 404
   - Логировать все запросы

3. База данных:
   - phone должен быть уникальным
   - email валидируется по формату
   - При удалении клиента - удалять его напоминания (CASCADE)

4. Особенно важно для ФРОНТЕНДА (у вас там больше всего ошибок):

   ❌ ЧАСТАЯ ОШИБКА:
   ```html
   <input type="text">  <!-- Нет name! -->
   ```

   ✅ ПРАВИЛЬНО:
   ```html
   <input type="text" name="client_name" id="client_name">
   ```

   ❌ ЧАСТАЯ ОШИБКА:
   ```javascript
   fetch('/clients')  // Не обработана ошибка
   ```

   ✅ ПРАВИЛЬНО:
   ```javascript
   fetch('/clients')
       .then(response => {
           if (!response.ok) throw new Error('Ошибка сервера');
           return response.json();
       })
       .then(data => {
           // Обработка данных
       })
       .catch(error => {
           alert('Ошибка: ' + error.message);
       });
   ```

ЧТО НУЖНО В ОТВЕТЕ:

1. Файлы:
   - main.py (FastAPI приложение)
   - database.py (модели SQLAlchemy)
   - schemas.py (Pydantic модели)
   - config.py
   - templates/index.html (главная страница)
   - static/style.css
   - static/script.js
   - requirements.txt
   - Dockerfile
   - .env.example
   - README.md

2. В HTML:
   - Подключить Bootstrap 5 из CDN
   - Адаптивная верстка (работает на телефоне)
   - Все формы с валидацией

3. В JS:
   - Функция для добавления клиента
   - Функция для удаления клиента
   - Функция для обновления списка
   - Обработка всех ошибок

4. Тестирование frontend:
   - Инструкция как открыть консоль браузера (F12)
   - Инструкция как проверить что данные отправляются
   - Что смотреть в Network tab при ошибках

НЕ НУЖНО:
- Сложные JS фреймворки (React/Vue) - только чистый JS
- Авторизация (добавлю потом)
- Сложный дизайн - простой и рабочий
```

### 3. Телеграм бот + Веб-интерфейс (гибрид)

```

Проект: Программа раскроя металла
Тип: Телеграм бот + Веб-интерфейс + AI
База данных: PostgreSQL
AI API: ChatGPT API для оптимизации раскроя

Создать систему для расчета оптимального раскроя металлических блоков

ТРЕБОВАНИЯ:

- SQLAlchemy + PostgreSQL
- OpenAI API для оптимизации алгоритма
- Three.js или Canvas для 3D

## ❓ Частые вопросы

### В: Почему Claude делает одну ошибку снова и снова?

**О:** Нет чёткого правила. Создайте RULES.md с правилами и в каждом промпте пишите "ВАЖНО: Следуй RULES.md"

### В: Почему фронтенд не работает?

**О:** Самые частые причины:
1. В `<input>` нет атрибута `name`
2. В JS нет обработки ошибок (`.catch`)
3. Backend возвращает не тот формат данных
4. Имена полей в HTML не совпадают с backend

Решение: используйте [специальный шаблон для фронтенда](#специальный-промпт-для-исправления-фронтенд-ошибок)

### В: Как проверить что данные отправляются на сервер?

**О:**
1. Откройте браузер (F12)
2. Вкладка Network
3. Нажмите на действие (кнопку отправить)
4. Смотрите запросы - там видно что отправилось и что пришло в ответ

### В: Тратится много токенов, как снизить?

**О:**
- Используйте `/compact` каждые 5 промптов
- Используйте `/clear` после завершения задачи
- Просите исправить ТОЛЬКО проблемное место
- Указывайте "НЕ НУЖНО: объяснения, альтернативы"
- Давайте примеры вместо длинных описаний

### В: Код работает в Python, но не в Docker?

**О:** Частые причины:
1. Не все библиотеки в requirements.txt
2. В .env неправильный DATABASE_URL для Docker (должен быть postgres:5432, а не localhost)
3. Порты не пробро шены в docker-compose.yml
4. БД не успела запуститься - добавьте depends_on

### В: ChatGPT API не работает в боте?

**О:**
1. Проверьте ключ в .env (OPENAI_API_KEY)
2. Проверьте баланс на счету OpenAI
3. Добавьте таймаут (30 сек минимум)
4. Добавьте логирование ошибок
5. Добавьте fallback если API не отвечает
