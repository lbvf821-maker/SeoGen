## 🔑 Основные принципы

### 1. Ясность и конкретность
**Правило золотой коллеги**: Покажите свой промпт коллеге с минимальным контекстом. Если они запутаются — Claude тоже запутается.

**❌ Плохо:**
```
Напиши функцию для обработки данных
```

**✅ Хорошо:**
```
Напиши Python-функцию parse_user_data(), которая:
- Принимает JSON-строку с данными пользователя
- Валидирует наличие обязательных полей: name, email, age
- Возвращает dict с провалидированными данными
- Выбрасывает ValueError с понятным сообщением при ошибке
```

### 2. Структурирование через XML-теги
Claude отлично понимает XML-структуры для разделения частей промпта.

### 3. Использование примеров (3-5 разнообразных)
Примеры должны быть:
- **Релевантными** — соответствовать реальному использованию
- **Разнообразными** — покрывать граничные случаи
- **Ясными** — структурированными через теги `<example>`

### 4. Разбиение сложных задач
Не пытайтесь решить всё в одном промпте. Используйте последовательность:
1. Анализ требований
2. Проектирование архитектуры
3. Реализация отдельных компонентов
4. Интеграция и тестирование

```xml

</context>

<task>
[Конкретная задача, которую нужно решить]
</task>

<requirements>

</requirements>

<constraints>
- [Ограничение 1: например, Python 3.10+]
- [Ограничение 2: например, не использовать библиотеку X]
- [Ограничение 3: например, максимальная сложность O(n log n)]
</constraints>

<examples>
<example>
<input>[Пример входных данных]</input>

</example>
</examples>

<output_format>
[Какой формат вывода ожидается: только код, код с комментариями, код + документация и т.д.]
</output_format>
```

## 🔧 Шаблон для исправления ошибок

### Принципы эффективного debugging-промпта

1. **НЕ регенерируйте весь файл** — просите изменить только проблемную часть
2. **Предоставьте полный traceback** — не только сообщение об ошибке
3. **Покажите контекст** — что вы пытались сделать
4. **Укажите уже проверенные решения** — чтобы не тратить токены на повторы

### Базовый шаблон для исправления ошибок

```xml
<error_context>
Файл: [путь к файлу]
Строки кода: [номера строк с проблемой]
Что должно работать: [ожидаемое поведение]
Что происходит: [реальное поведение]
</error_context>

<error_details>
<type>[Тип ошибки: TypeError, ValueError, AttributeError и т.д.]</type>
<message>
[Полное сообщение об ошибке]
</message>
<traceback>
```
[Полный traceback]
```
</traceback>
</error_details>

<code_snippet>
```python
# Проблемный участок кода (минимальный необходимый контекст)
[код]
```
</code_snippet>

<attempted_solutions>
Уже пробовал:
1. [Решение 1] - результат: [что получилось]
2. [Решение 2] - результат: [что получилось]
</attempted_solutions>

<constraints>
- НЕ изменяй логику работы других частей функции/класса
- НЕ меняй сигнатуру функции (если не критично)
- Сохрани существующие переменные и их назначение
- [Другие ограничения]
</constraints>

<output_format>
Предоставь:
1. Объяснение причины ошибки (1-2 предложения)
2. ТОЛЬКО исправленный участок кода (не весь файл!)
3. Если нужно изменить несколько мест — покажи их отдельно с указанием строк

НЕ включай:
- Полную копию файла
- Объяснения базовых концепций Python
- Альтернативные подходы (если не запрошены)
</output_format>
```

## ⚡ Оптимизация расхода токенов

### Стратегии снижения затрат

#### 1. Управление контекстом сессии

**Команды Claude Code:**
- `/clear` — очистить весь контекст (используйте при смене задачи)
- `/compact` — сжать историю, сохранив ключевую информацию
- `/cost` — проверить расход токенов

**Когда использовать /clear:**
- Завершили задачу и переходите к несвязанной
- Накопилось много неактуальной информации
- После нескольких итераций отладки одной проблемы

**Когда использовать /compact:**
- Долгая сессия работы над одной функциональностью
- Нужно сохранить контекст, но сократить объём

#### 2. Эффективная подача контекста

**❌ Не делайте:**
```
Вот весь мой проект (15000 строк кода). Добавь функцию валидации email в модуль users.
```

**✅ Делайте:**
```xml
<context>
Файл: src/users/validators.py
Существующие валидаторы: validate_username(), validate_password()
Стиль: используют регулярные выражения, возвращают tuple (bool, str | None)
</context>

<task>
Добавь функцию validate_email() в том же стиле
</task>
```

**Экономия:** ~90% токенов на контексте

#### 3. Точечные изменения вместо регенерации

**❌ Не делайте:**
```
Перепиши функцию полностью, изменив условие в строке 45
```

**✅ Делайте:**
```xml
<edit_request>
Файл: utils.py
Функция: process_data() (строки 40-60)
Изменение: В строке 45 замени условие `if x > 0:` на `if x >= 0:`

Покажи только изменённые строки с контекстом ±2 строки
</edit_request>
```

**Экономия:** ~80% токенов на вывод

#### 4. Использование файла CLAUDE.md

Создайте файл `CLAUDE.md` в корне проекта для постоянного контекста:

```markdown
# Проект: [Название]

## Технологии
- Python 3.11
- FastAPI
- SQLAlchemy 2.0
- Pydantic v2

## Архитектура
- src/api/ — эндпоинты
- src/models/ — ORM модели
- src/schemas/ — Pydantic схемы
- src/services/ — бизнес-логика

## Стиль кода
- Type hints обязательны
- Docstrings в формате Google
- Линтер: Ruff
- Форматтер: Black

## Частые паттерны

### Создание API эндпоинта
```python
@router.post("/resource", response_model=ResourceSchema)
async def create_resource(
    data: ResourceCreate,
    db: Session = Depends(get_db)
) -> Resource:
    """Create a new resource."""
    return await ResourceService.create(db, data)
```

### Обработка ошибок
```python
from src.exceptions import NotFoundError

if not item:
    raise NotFoundError(f"Item {id} not found")
```

## Анти-паттерны (НЕ делать)

❌ Не использовать `.format()` — используй f-strings
❌ Не делать `except Exception:` — ловить конкретные исключения
❌ Не смешивать sync/async без необходимости
```

**Важно:** Держите CLAUDE.md компактным (до 5000 токенов), так как он читается при каждом запросе.

#### 5. Разбиение сложных задач (Prompt Chaining)

**❌ Один большой промпт:**
```
Создай систему авторизации с JWT, регистрацией, входом, восстановлением пароля,
OAuth через Google и Facebook, rate limiting, и админ-панелью.
```
Результат: хаотичный код, пропущенные детали, много токенов.

**✅ Последовательность промптов:**

**Промпт 1: Архитектура**
```xml
<task>
Спроектируй архитектуру системы авторизации с JWT для FastAPI приложения.
Предоставь только структуру модулей и основные интерфейсы, БЕЗ реализации.
</task>
```

**Промпт 2: Базовая аутентификация**
```xml
<context>

</context>
<task>
Реализуй базовую аутентификацию (регистрация + вход с JWT)
</task>
```

**Промпт 3: Расширение функционала**

## ❗ Типичные ошибки и как их избежать

### 1. Повторяющиеся однотипные ошибки

**Проблема:** Claude постоянно делает одну и ту же ошибку (например, забывает проверку типов)

**Решение:**
```xml
<important_rule>
КРИТИЧЕСКИ ВАЖНО: В этом проекте ВСЕ функции ДОЛЖНЫ иметь:
1. Type hints для всех параметров и возвращаемого значения
2. Проверку типов через isinstance() для внешних данных
3. Docstring с описанием параметров

Пример обязательного паттерна:
```python
def process_item(item: dict[str, Any]) -> ProcessedItem:
    """Process item data.

    Args:
        item: Raw item dictionary with keys: id, name, value

    Returns:
        ProcessedItem instance

    Raises:
        ValueError: If required keys are missing
    """
    if not isinstance(item, dict):
        raise TypeError(f"Expected dict, got {type(item)}")
    # ...
```

НЕ ГЕНЕРИРУЙ КОД, который не соответствует этому паттерну.
</important_rule>
```

Поместите такие правила в CLAUDE.md для постоянного применения.

### 2. Конфликты при слиянии изменений

**Проблема:** Claude перезаписывает изменения, сделанные в других частях файла

**Решение:** Используйте явное указание границ изменений

```xml
<edit_instruction>
Файл: src/utils.py

ИЗМЕНЯЙ ТОЛЬКО функцию calculate_total() (строки 45-67)

НЕ ТРОГАЙ:
- Функцию calculate_tax() (строки 1-20)
- Функцию format_currency() (строки 70-85)
- Импорты

Покажи в ответе ТОЛЬКО изменённую функцию calculate_total()
</edit_instruction>
```

### 3. Излишняя абстракция или усложнение

**Проблема:** Claude создаёт слишком сложные решения для простых задач

**Решение:**
```xml
<simplicity_requirement>
Требуется ПРОСТОЕ решение:
- Без фабрик, builder-ов и абстрактных классов
- Без избыточных слоёв абстракции
- Без "enterprise patterns" если не требуется
- Код должен быть понятен junior-разработчику

Если задачу можно решить простой функцией — используй функцию, а не класс.
</simplicity_requirement>
```

### 4. Игнорирование граничных случаев

**Проблема:** Код работает на базовых примерах, но падает на реальных данных

**Решение:** Всегда включайте тест-кейсы

```xml
<mandatory_test_cases>
Код ДОЛЖЕН корректно обрабатывать:
1. Пустые входные данные (None, [], {}, "")
2. Некорректные типы данных
3. Экстремальные значения (0, -1, очень большие числа)
4. Unicode и спецсимволы в строках
5. [Специфичные для задачи случаи]

Включи проверки для КАЖДОГО случая.
</mandatory_test_cases>
```

### 5. Потеря контекста при длинной сессии

**Проблема:** После 10+ промптов Claude "забывает" важные детали

**Решение:**
- Используйте `/compact` каждые 5-7 промптов
- Периодически напоминайте ключевые правила:

```xml
<reminder>
Напоминание о контексте:
- Проект: FastAPI REST API
- Все эндпоинты асинхронные (async def)
- Используем Pydantic v2 (НЕ v1)
- Обязательны type hints
</reminder>

<task>
[новая задача]
</task>
```

### 6. Неявные зависимости

**Проблема:** Claude генерирует код, который зависит от несуществующих модулей

**Решение:**
```xml
<available_modules>
Используй ТОЛЬКО эти библиотеки (они установлены):
- fastapi
- pydantic==2.5.0
- sqlalchemy==2.0.23
- python-jose[cryptography]

НЕ ИСПОЛЬЗУЙ:
- Библиотеки, не перечисленные выше
- Собственные модули, которых нет в проекте

Если нужна новая библиотека — СНАЧАЛА спроси, можно ли её добавить.
</available_modules>
```

### 7. Несоответствие стилю проекта

**Проблема:** Новый код выглядит чужеродно

**Решение:** Предоставьте примеры существующего кода

```xml
<style_reference>
Пример существующего кода в проекте:

```python
# src/services/user_service.py
class UserService:
    """Service for user operations."""

    @staticmethod
    async def get_by_id(db: Session, user_id: int) -> User | None:
        """Retrieve user by ID.

        Args:
            db: Database session
            user_id: User identifier

        Returns:
            User instance or None if not found
        """
        result = await db.execute(
            select(User).where(User.id == user_id)
        )
        return result.scalar_one_or_none()
```

Новый код должен следовать этому же стилю:
- Классы-сервисы со статическими методами
- Async везде, где работа с БД
- Type hints с | для Union (Python 3.10+)
- Docstrings в формате Google
- Явные импорты (не from x import *)
</style_reference>
```
